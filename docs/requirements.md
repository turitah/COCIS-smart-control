# Requirements checklist

Derived from the coursework PDF, Sections 2.1–2.7.

- [ ] Main entrance RFID identifies registered and unregistered cards.
- [ ] Entry and exit are recorded at their respective points.
- [ ] Building occupancy state remains consistent; duplicate/invalid movements do not corrupt it.
- [ ] Lecture Room 1 independently detects occupancy and controls lighting.
- [ ] Lecture Room 2 independently detects occupancy and controls lighting.
- [ ] Three ESP32 terminals have a documented communication/coordination approach.
- [ ] SD-card storage persists relevant access and system records.
- [ ] Serial management commands show logs, occupancy, room and lighting states.
- [ ] Authorized administrator can change the access schedule.
- [ ] Unauthorized configuration attempts are rejected.
- [ ] Synchronization prevents inconsistent shared records/race conditions.
- [ ] Failure cases and recovery are demonstrated.
- [ ] Report, Wokwi link(s), individual videos, contributions, member details and presentation are ready.

## Evidence convention
For each checkbox, record: owner, test steps, expected result, observed result, and evidence link/screenshot.
